# X 征集需求整理

人在 X 上发一条征集帖，打开自己帖子的详情翻看回复；Agent 读取这些回复，归类成需求清单、统计热度，并为值得回复的人起草回复，交给人确认后发出。
桥只做桥：这份配方是给 Agent 的提示模板，分析在 Agent 里做；**发帖、回复永远由人自己点「发布」**。

## 需要

- 平台包 `x`（映射卡 `x/post`、`x/reply`；实体类型 `post`、`comment`）
- 插件「X」与「X 帖子与回复」已启用（控制台「插件」页 X 卡为「已启用」）
- 人在 X（网页或应用）打开自己征集帖的详情，往下翻回复；只采到看过的回复

## 帖子与回复的字段

帖子 `post`：`id, title（正文）, author, handle, create_time（秒）, view_count, like_count, retweet_count, reply_count, quote_count, bookmark_count, url`

回复 `comment`：`id, post_id（所属帖子）, reply_to（"0" = 直接回复帖子，否则是上级回复的 id）, nickname, handle, content, like_count, reply_count, view_count, create_time（秒）, reply_to_nickname, image, url`

## Agent 提示模板

把下面整段作为任务说明给 Agent：

```
你通过囤囤鼠的 MCP 工具读取我在 X 上看过的回复，整理我发的征集帖收到的反馈。数据只来自我已经看过的页面，不要尝试抓取；不要替我发帖、回复、点赞或私信。

输入：我的征集帖链接（https://x.com/<handle>/status/<帖子 id>）或帖子 id。
没给的话：调用 query_entities(platform="x", kind="post", keyword=<我说的关键词>) 找出候选，让我确认是哪一条。

流程：
1. 调用 get_thread(platform="x", kind="post", id=<帖子 id>, limit=500)，拿到帖子和回复树（楼中楼在 replies 里）。
2. 逐条归类，每条回复一个主类，可附次类：
   - 功能需求：想让它做什么（新功能、改进）
   - 平台请求：想支持哪个平台或网站
   - 问题与疑虑：隐私、安全、价格、上手难度、平台规则
   - 试用意向：想试用、要链接、要加候补
   - 认同与其他
3. 合并意思相同的需求，记下提到的人数（按 handle 去重）和点赞合计（like_count 相加），按 人数 → 点赞 排序。
4. 每条需求附 1~2 条原文引用（content 原样，带 @handle）。
5. 起草回复，对象是：提了具体需求或问题的、点赞最高的前 5 条、表达试用意向的。要求：
   - 用对方的语言回复；具体、诚恳，不营销、不承诺上线日期；不 @ 与这条回复无关的人。
   - 每条草稿附「去回复」链接：https://x.com/intent/post?in_reply_to=<回复 id>&text=<草稿，URL 编码>
     我点开后 X 会打开已填好的回复框，由我自己点发布。
6. 需要我判断的回复（回不回、怎么回、要不要做），单独列一张表：回复给 @handle | 对方原文 | 为什么要我判断 | 链接。
7. 输出：
   - 概览：采到的回复数 / 帖子显示的回复总数（reply_count）/ 各类数量
   - 需求清单表：需求 | 人数 | 点赞合计 | 引用
   - 平台请求排行
   - 问题与疑虑，以及建议的统一回应口径
   - 回复草稿表：回复给 @handle | 对方原文 | 草稿 | 去回复链接
   - 提醒我：在 X 里继续往下翻回复，说「更新」就增量整理
8. 我说「更新」时：再调用一次 get_thread，只处理上次没见过的回复（按 id 对比），合并进需求清单并标出新增。

约束：不替我做判断（回不回、做不做、收不收藏由我来）；引用保留原文，不改写；不编造回复里没有的信息；不修改或删除任何映射。
```

## 输出示例（结构）

| 需求 | 人数 | 点赞合计 | 引用 |
|---|---|---|---|
| 支持抖音评论整理 | 7 | 41 | 「抖音能不能也像小红书这样……」@example |
| 导出到飞书多维表格 | 3 | 12 | 「整理完能直接进飞书就好了」@example |

| 回复给 | 对方原文 | 草稿 | 去回复 |
|---|---|---|---|
| @example | 数据会上传吗？ | 不会，全部只存在你自己电脑上…… | x.com/intent/post?in_reply_to=… |

## 已知边界

- 桥只存人看过的页面：X 的帖子详情默认只展开一部分回复，往下翻、点「显示更多回复」才会继续进来。
- 回复时间、点赞数是看到那一刻的数；之后再看一次会更新。
- 「去回复」链接只能带文字，配图要在 X 的回复框里自己添加。
